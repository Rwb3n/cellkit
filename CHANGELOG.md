# Changelog

## Unreleased

**Commands**
- **`cell land` accounts for git-ignored files in the cell's worktree** (#77; COCKPIT). Git never shows them, so a land never did either: COCKPIT's root listed them by hand before every landing, after a cell left 8 MB of real-data output in an ignored `test/tmp/`. Now every land and dry run lists them, largest first, with file counts and sizes. Only the views fold writes are left out (`state/views/<name>.json`, the root's or a cell's; by place and extension, so a file given such a name there is not seen): a cell's own `node_modules/` is listed. A project that sets `land.ignored` in bedrock `guards.json` (globs from the worktree's root; an empty list allows none; the obvious catch-alls, `**` or `**/*.*`, are refused) gets a refusal instead: before the land starts while any other git-ignored file is there, and again after `--check`, undoing the land, if the check left one. There is no flag to land past it: delete the file, or the operator approves it into the list. A check that leaves files git does show (not ignored) is said in the report, the dry run's too, not refused. An undo now says "back where it was" only after checking the branch is: when its own git commands fail (a check that broke the worktree's index), it says the branch could not be put back. Not done: a nested git repository in the worktree is not looked inside (#92); whether to refuse the plain files a check leaves is the operator's call (#93); `cell audit` doesn't list ignored files; there is no size limit.
- **`cell land` says what its check ran without** (#68; ecom-lab). `--check` runs in the cell's worktree, which holds tracked files only. A test that ran a real adapter against the repo root found no `data/` there and passed; in the main checkout and in production, where `data/` is real, it failed. A land with a check (and its dry run) now names the git-ignored paths the main checkout holds files in and the worktree doesn't (an empty folder of the same name doesn't count as having them), beside the check's result. The check is not run a second time in the main checkout: a cell's tests would then run against the real data. The cell brief gains the rule: tests read a committed fixture or a temp folder, never the repository root or a git-ignored folder.
- **`cell land` prints a reply's "Decisions to confirm"** (#74; apify-actor-dev). A cell's reply listed "Caption not read: the research didn't use it" under that heading; root landed the work, the decision reached nobody, and it shipped as a product limit a buyer found a day later. The cell brief now asks every reply to end with a **Decisions to confirm** section (each choice the task didn't make, or `none`). A land, and its dry run, ends by printing that section for each reply it lands (the reply entries its branch adds to the cell's log; the text comes from root's mailbox, so it works with `mail.log: "hash"` too), or says a reply has no such section. It prints, after the sync and root's log commit (and even when those fail), so it is the last thing on the screen; it doesn't refuse. Reading the section errs towards printing: only the brief's heading counts, every such section is read, one under a `#` heading ends at the next heading of its level or above and any other runs to the next `#` heading or the reply's end, and it is silent only when every line of it says none. So a reply with more text after a "none" prints that text too: end the reply with the section, as the brief says. `templates/ROOT.md` ("When a cell replies") says to take each to the operator or log it. Not done: lint doesn't check that a listed decision has a log entry.
- **`cell land` stops on what its check can't see: values a cell overturned, and a test that was weaker only while the cell worked** (#72; COCKPIT). Two things landed there under a passing check. A cell corrected values it had been given (2 of the 3 expected labels in root's own backbrief, a design's timeline): the corrections were right, but nobody except the cell had checked them, and a cell writes both the code and the test that holds the new value. And for a proof a cell switched a guard assertion off with `sed`, ran the proof and restored the line: the final tree was clean.
  - **Overturned.** The brief asks every reply for a second closing section, **Overturned**: each value the task, a design or root's brief gave that the work changed, with the evidence, or `none`. It is read exactly as "Decisions to confirm" is. A land that would land one with items refuses, before anything changes, until root says what it checked against which source: `--checked "<…>"`, which goes into the merge commit with the items. An empty `--checked` is no check, and `--checked` with nothing overturned is refused, so it is never typed out of habit. A reply with no such section is said, not refused; one whose text can't be read (`mail.log: "hash"` and no copy in root's mailbox) is refused (with bodies kept out of the log, a second machine has no copy: every landing there needs `--checked`). "Overturned" as a list item inside another section starts an Overturned section too, without ending the one it is in (what follows is shown under both). Text after a "none" reads as an item: the refusal says how to record that nothing was overturned.
  - **Weaker during the run.** In a cell session the shell hook, before each command, writes down the commit the worktree is on and the bytes of each of its test files that differ on disk, in the cell's mailbox (in no checkout; the cell's guards keep it out). It judges nothing. A land reads the record and compares each state with where the cell had left the branch being landed on at that time, so what main itself changed is never the cell's, wherever root's checkout sat and whatever the trunk is called. A finding that isn't in the tree being landed stops the land like any weaker test ("were weaker during its run than they are now"), and `--accept-weaker` (the operator's) lands it with the finding in the merge. The record is cleared when the work lands. Every test file is read and its bytes compared with the commit's, so what changes git's view of a file doesn't hide a test (`assume-unchanged`, a diff attribute, an edit with the old modification time put back); left out are files over 1 MB, files another program holds open, and bytes git itself would store as the commit's (line endings, a filtered fixture); git's own comparison (the land's, of the tree being landed) now ignores settings that would empty or rename its output (an external diff, a textconv, `diff.mnemonicPrefix`, pathspec variables in the environment, `git replace`) and reads files an attribute calls binary. A record that can't be written refuses the command; a line, a commit or a state of it that can't be read is a finding. Two older holes closed with it: a test file with a space in its name was never compared, and a comparison git couldn't make counted as "nothing weaker" (it now stops the land). `--accept-weaker` with nothing weaker is now refused, as `--checked` with nothing overturned is. It will also catch a cell that rewrites a test in two edits with a command between them, if the half-way state has fewer cases or assertions. Not seen: a test weakened and restored inside one single command (#82), and an edit undone before any command ran.
- **`mail.ts watch`: one watcher per box** (#90; ecom-lab). `watch` marks mail read, so of two watchers on one box whichever wakes first takes the reply: root had one waiting in the background for a cell's reply, then started a second with its output thrown away. A watch now holds a lock in the box for its life. A second that could take the same mail is refused (exit 1), naming the first's pid and start time; `--steal` takes over, and the first ends (exit 3) without taking anything. Watchers with `--for <id>` for different messages run side by side; a whole-box watch conflicts with any. A killed watcher's lock counts for nothing (if its pid has since been reused by a live process, the refusal says so and `--steal` clears it). `watch`, `status` and `release` now refuse `--as <a name that is no cell>`. `mail.ts status` shows `watched_by` while one lives.
- **`cell land`'s refusal over an untracked root file names the way out** (#89; ecom-lab). The operator's `.vscode/settings.json` stopped a verified landing as "root's uncommitted work". It still does: root's own new files look the same, and nothing unaccounted for sits in root when a cell lands. The refusal now says which of the paths are untracked and that a file that isn't the project's goes in `.git/info/exclude`.
- **A cell's reply is no longer lost when its session takes its own mail** (#101; ecom-lab). A headless session, started as always with "waiting for mail", didn't end its turn: it looked for the mail, found `mail.ts watch`, and ran it from its own folder. `watch` marked the task read without making it the one in flight, the session did the work, and at its stop nothing was in flight, so no reply was filed. Two tasks of three went that way, each run exiting 0 with `working_on` empty; root found the work by reading the worktree. Now:
  - **Only root watches, and only root's box.** `watch` (and `recv`) refuse a cell's box, and refuse every box from a cell's session, root's included (the next thing a session tries is `--as root`, which took other cells' replies). They say what to do instead: end the turn, and the Stop hook hands the task over. The task stays queued. The brief says the same in a sentence. A folder inside a cell now counts as the cell for every mail command: from `cells/<x>/adapters` a session used to be root. And root's mail is handled from the main checkout only: `send`, `watch` and `release` run as root from the root of a cell's worktree (which is no cell's folder) are refused; `status` stays open.
  - **`status` lists `unanswered`**: tasks a cell took that have no reply and are not in flight. None should exist; this is the check that says so when one does. A headless run that ends with one tells root with a `blocked` mail naming the task, the worktree and the transcript, once per task (whichever run left it), and exits 8 where it would have exited 0.
  - **`mail.ts release --as <cell> --for <id> [--note "…"]`** files the reply for such a task, in root's words, after root has read what was done. Refused while a run is live for the cell.
  - **A blank answer is still a reply.** An answer of only spaces or newlines made the Stop hook fail after the task had stopped being in flight; it is now filed as "(no answer text)".
- **`cell land` rebuilds the worktree's views from the merged log before its check** (#102; ecom-lab). Views are git-ignored, so the merge of main into the cell's branch never touches them: a cell had folded the root views in its worktree, root then logged an assumption on main, and the land's check compared a table generated from the merged log with the older views (`KeyError: 'A51'`). The land was undone, correctly, and root deleted the views by hand. Now, after merging and before the check, a land rebuilds the views the worktree already holds (the root's and each cell's; none are made where there were none) and names those that were behind; an undo rebuilds them again, so they follow the log back. `cellrun` does the same after the merge it makes before a session starts. A land whose worktree holds views it can't rebuild (a log entry that can't be read, in any cell there) is undone, naming the folder: mend the log (`lint --all` says which entry), or delete that folder's `state/views` in the worktree to land without them.

**Upgrading a project** (so far)
- `mail.ts watch --as <cell>`, and any `watch` run from a cell's folder or a folder inside it, now refuses, exit 1. Nothing in the kit's docs ever used either; a script of your own that did was taking tasks whose replies were then never filed. A root session that runs mail commands with its working directory inside `cells/<x>` (and no `CLAUDE_PROJECT_DIR`) is now that cell: run them from the repository root, as every kernel command. Root's `send`, `watch` and `release` work from the main checkout only: from the root of a cell's worktree, or from one of Claude Code's own worktrees (`.claude/worktrees/`), they are refused.
- `cellrun` has a new exit code, 8: the session exited 0 and a reply is not coming (a task still in flight with no answer in the run log, which used to exit 0, or one found taken with no reply and not in flight). Root is told by mail either way.
- `mail.ts status --as <cell>` may show `unanswered` for old tasks that were lost this way (ecom-lab has two). Read the worktree and the run log, then clear each with `mail.ts release --as <cell> --for <id> --note "…"`.
- `cell refresh --name <cell>` for each cell, to take the brief's new rules (tests read only what is committed; a proof runs on a copy of a test; a reply ends with "Decisions to confirm" and "Overturned"; told "waiting for mail", end the turn and never fetch the mail). Until then a land says each reply has no such section.
- `cell land` prints up to four new items (git-ignored files in the worktree, what the check ran without, what the check left, the reply's decisions to confirm); nothing of these is refused until the project sets `land.ignored`.
- Two new refusals in `cell land`: a reply with "Overturned" items needs `--checked "<what root checked, against what>"`; a test that was weaker while a command of the cell's run ran needs the operator's `--accept-weaker`. The shell hook now runs two or three `git` commands and reads every test file before each command of a cell session, and keeps a record per cell under `.git/cellkit-mail/<cell>/` (`weaker.jsonl`, `weaker/`), cleared at each landing.
- A second `mail.ts watch` on a box that a live one holds now exits 1 instead of racing it. Scripts that start a watch per cell should pass `--for <task id>`, or use one watch for the box. New exit code: 3, a watch that was taken over.

## v0.6 — guards that judge acts, landings that check first (2026-10-28)

The v0.6 milestone: #55, #60, #63, #67, #71, #73, #75, #76, #81, from COCKPIT, ecom-lab, portofolio-manager and modelkit. The guard changes (#60, #75, #81) had five rounds of adversarial review before release, each fixing what the last found; the gaps v0.5 had too are #84.

**Docs**
- **Kernel commands run from the repo root** (#67; COCKPIT). An operator who ran `! node kernel/src/cli.ts …` from a subfolder got Node's bare MODULE_NOT_FOUND. README (Quick start, Traps) and the `AGENTS.md` template now say so. Still open: a wrapper that finds the root itself.
- **Kit commits close only the kit's issues** (#55; modelkit). Merging v0.4.0 closed modelkit's own open PR #1 and issue #2: GitHub applied the kit's `Fixes #1`, `Fixes #2` to modelkit's numbers. Kit commits now write `Fixes Rwb3n/cellkit#N`. Earlier ones can't be rewritten: this range still holds bare `Fixes #60`, `#63`, `#71`, `#75`, `#81`. README ("Using it in a project") gives the check to run before pushing a kit merge.
- **Take a kit update in a scratch clone** (#63; portofolio-manager). A `git merge cellkit/main` that stopped with conflict markers in `hook-bash.ts` and `hook-guard.ts` locked the session out: every guard failed closed, and only the operator's `! git merge --abort` recovered it. README ("Using it in a project") now gives the procedure that worked there: merge, resolve and test in a clone, then `git pull --ff-only` from it, which can't stop half-done. Still open (#83): a guard that spots conflict markers and says so in one line instead of a stack trace, or a `kit update` command that does all this.

**Commands**
- **`cell land --dry-run` runs the check** (#76; COCKPIT). The dry run only printed `--check`: COCKPIT's came back clean, then the real land refused 20 minutes later, because cmd.exe doesn't scope a `cd` inside `( … )`. Now the dry run runs the check in the worktree as it stands (before the merge; the real land runs it after), says whether it passes, with the last lines if not, and names the shell it runs under.
- **`cellrun --effort <level>`** (#73; COCKPIT). A project's model policy sets a cell's model and effort; `cellrun` passed `--model` but had no way to pass `claude --effort`, so COCKPIT wrapped `claude` in a `.cmd`. Now `--effort` (low, medium, high, xhigh, max) goes on the command like `--model`, and the run's `.exit` note records both: the stream's init event shows the model but not the effort.

**Fixes**
- **A kernel-owned path and a write are one act only in one pipeline** (#81; COCKPIT). The text check refused a command that named a kernel-owned path anywhere and wrote anywhere: `git add docs/assumptions.md && printf … > /tmp/msg.txt` was refused as writing `docs/assumptions.md`. Now the path and the write must stand in the same pipeline (laid out over lines or not, with the shell strings it runs: `echo state/log/x | xargs rm`, `sh -c '…' | xargs rm` and `'docs/assumptions.md' | Clear-Content` are one act), or the same piece of program code (a heredoc's path and its `open(…, 'w')` may be lines apart). A write to a target built from a variable (`f=state/log/x; echo y > $f`), or one that names a variable (`$p = 'state/log/x'; [IO.File]::WriteAllText($p, …)`), can't be judged, so with a kernel-owned path named anywhere the whole command still counts. Still refused, as before: a read of a kernel-owned file redirected elsewhere in one command (`cat state/log/x.json > out.json`).
- **The read guard reads a script's paths, not its prose, and a pipeline isn't a folder** (#60; ecom-lab, COCKPIT). Two refusals of commands that read no secret:
  - a Python heredoc that edited a doc, with "this project's `.env`" in a replacement string: in code that reads files, every token was a path. Now each string literal is judged whole as one path, and each argument of a read call (`readFileSync(…)`, `open(…)`) token by token, which a stray quote elsewhere can't hide: `'.env'`, `f"{root}/.env"` and `` `${cwd}/.env` `` still read it; a sentence that names it is text. Still refused: a literal that is a sentence ending in a secret's name (`"edit the .env"`).
  - `schtasks /Query … | Select-String "TaskName|Status"`: a `Select-String` with no path was judged as a search of the current folder. It reads what feeds it, and that is text only when every command up the pipeline is a known text producer (`git`, `npm`, `dotnet`, `docker`, `schtasks`, `Get-Process`, `echo`, … : `TEXT_PRODUCERS` in `secrets.ts`) with no expression in it (`echo (gci -r)` passes files). Then a `Select-String`, `sls` or `Get-Content` with no path is allowed; fed by anything else, it is judged as before, as a search of the current folder. An allowlist on purpose: four rounds of review each found a way around a finer reading of which commands list files (wrapped listings, variables, `Invoke-Command`, patterns that still select `.env`). So `gci -r -Filter *.ts | Select-String KEY` is still refused in a folder holding a secret: give Select-String the files (`-Path src/*.ts`).
  - Newly refused: `(cat .env)` and `gci -r | sls KEY` passed v0.5 (a leading paren, and the `sls` alias). The read guard judges each line on its own: in PowerShell, `cd src \` and a read on the next line are two commands.
- **A new test file can't be weaker** (#71; ecom-lab). `cell land` refused a cell whose brand-new `test_colleague.py` held four `pytest.approx` float assertions, as "loosened": the check counted the new file's lines like any diff. A file the branch creates now reports nothing. A test moved out of an old file still shows there as fewer cases, and a tolerance added to an existing file is still loosening. Still open: a new `approx` assertion added to an existing file counts as loosening, whatever the old line was.
- **A subshell's parens end a word** (#75; COCKPIT). `(ls x 2>/dev/null)` read the redirect's target as `/dev/null)`, and a cell was refused writing outside itself. A subshell's parens (where a command starts, and their match) now end a word and a command, so the null device is the null device, and a `cd` inside a subshell is followed until the subshell closes, by the write guard, the cell boundary and the read guard: `(cd .. && echo x > y.txt)` in a cell passed before, and is now refused; `(cd /tmp) && rm -rf state/log` is judged from the repo, as the shell runs it. A `case` pattern's `)` closes no subshell. An argument's parens stay in its word (PowerShell's `-Path (Join-Path . state)`).


**Upgrading a project to v0.6**
- **Take the update in a scratch clone** (README, "Using it in a project"): merge, resolve, run the tests there, then `git pull --ff-only` from it. A merge that conflicts in a guard hook locks the session out (#63).
- **Before pushing the merge, check what its messages close** (#55): `git log <your previous kit tag>..v0.6.0 --format=%B | grep -iE "(fix|close|resolve)[a-z]* #[0-9]+"`. This range holds bare `Fixes #60`, `#63`, `#71`, `#75`, `#81`, which GitHub applies to *your* numbers. Reopen what they close, or push the merge where no issues share those numbers.
- No settings, `.gitignore` or cell changes. `cell refresh` is not needed.
- Newly refused for sessions:
  - `gci -r | sls KEY` (v0.5 didn't know the alias), and a `Select-String` or `Get-Content` with no path fed by a listing through any wrapper or pass-through, in a folder that holds a secret;
  - `(cat .env)`;
  - a pipeline that names a kernel-owned path and writes;
  - in a cell, a write after a `cd` inside a subshell that leaves the cell: `(cd .. && echo x > y.txt)`.
- Newly allowed: a kernel-owned path named in one command and a write in another (`git add docs/assumptions.md && printf … > /tmp/msg`); a subshell's redirect to the null device; a `Select-String` reading a known text producer's output (`schtasks … | Select-String`, `npm run build | Select-String error`); a new test file's tolerances.
- `cell land --dry-run` now **runs** `--check`, in the cell's worktree. A check with side effects has them on a dry run too.

## v0.5 — guards that hold (2026-10-23)

The v0.5 milestone: #3, #4, #5, #6, #7, #38, #49, from callsheet, AI-MMO, processkit and apify-actor-dev.

**Commands**
- **`cli.ts <command> --help`, and a refusal names every missing flag** (#6; apify-actor-dev). Flags were learnt by grepping `cli.ts` for `opt(`: `assume` said "needs --statement", then the next run named the next flag. One table in `cli.ts` now holds every command's usage and the flags it needs: `--help` prints a command's (`cell land --help`) or all of them (`--help`), and a command missing flags is refused naming all of them with its usage line, before it writes anything. An unknown command or subcommand prints the usage of its group.

**Fixes**
- **`<name>.env` is a secret** (#5; callsheet). The read guard's defaults matched `.env` and `.env.*` only: callsheet's instrument kept its key in `vein.env` and renamed it to be covered. Now `<name>.env` and `<name>.env.<x>` are denied too, never `*.env.example`, and a search over a folder holding one must be narrowed. `process.env` in code is not a file.
- **Lint's approval hint is the command that works** (#4; callsheet). `init` registers the starter ontology as a draft; an amend on top leaves two proposals pending, and lint's hint (`approve --doc ontology`) was then refused for want of `--proposal`: callsheet's operator ran it twice. With several pending, lint now lists them and names the newest (`approve --doc <doc> --proposal <newest>`; approving it drops the older ones, the starter included), and approve's refusal ends with the same command. A doc with one proposal pending on top of an approved version now gets the hint too.
- **git's deletes are writes** (#3; AI-MMO, processkit). Tested in a throwaway repo:
  - `git reset --hard`, `--keep` or `--merge` to an earlier commit deleted the log entry committed since;
  - `git clean -f`, `git stash -u` and `-a` took away one not yet committed, and plain `git stash` a staged one;
  - `git reset --hard` (to HEAD) reverted a modified tracked file, as it would an approved bedrock doc before its commit.

  The shell guard now refuses `clean` that deletes and every `stash` push or save, wherever their pathspecs hold a kernel-owned path (none given = the whole checkout), `reset --hard` whatever the commit, and `reset --keep/--merge` to a commit other than HEAD, in this repository or a cell's. Undo a commit with `git revert` (a landing: `git revert -m 1 <merge>`, as `cell land` prints); restore a file by name; the operator resets from their prompt. Still open: `reset --mixed/--soft`, `--keep/--merge` to HEAD, `stash pop/list`, `clean -n`, `clean -fdX` (ignored files only: views, locks), these on other paths (`git stash push -- src/`, `git clean -fd build/`) or in another repository. Git commands now follow a `cd` before them, like the other write targets.
- **A kernel-owned folder named without its slash is kernel-owned** (#49). `rm -rf state/log`, `rmdir state/bedrock`, `mv x.json state/log` and a script's `rmSync('state/views', …)` passed the shell guard, which matched only `state/log/` with the slash. And a path deleted or moved away (rm, mv's sources, a script's `rmSync`, `renameSync`, `shutil.rmtree`, `os.remove`) may no longer hold one: `rm -rf docs`, `rm -rf state`, `rm -rf .`, `rm -rf *`, `rm -rf cells/<x>`, `mv docs old`. Targets follow a `cd` before them (`cd state && rm -rf log`), and on Windows a Git Bash path `/d/x` is `D:/x` (root's own session deleted its views with `cd /d/PROJECTS/cellkit && rm -rf state/views` while testing this; before, any `/d/…` absolute target missed the repo). Still open: fixtures (`test/fixtures/x/state/views`), `rm *.tmp`, writing into `docs/`, `state/out/`, and `state/bedrock/proposed` (now with or without its slash).
- **A guard that can't load refuses** (#38). A hook script with a syntax error or a broken import exits 1 (127 with no `node` to run it), and Claude Code blocks only on exit 2: a broken guard was no guard (tested with `claude -p`, 2.1.295, a syntax error: the command ran). Every guard's hook command now ends `|| exit 2`, in the template's root `.claude/settings.json` and in every cell's (`cell new`, `cell refresh`). The session sees the hook's error as the refusal.
- **A cell's views no longer show stale after every land** (#7; callsheet). Mail appended the task and its reply to the cell's log and to root's without refolding, so root's `lint --all` warned "views are stale" after every task; and `fold --cell cells/<x>` run from main folded the main checkout's copy (a snapshot from the last land), not the live log in the cell's worktree that lint reads, so the warning stayed. Now every write refolds the log it wrote, mail included (`refold.ts`, under the log's lock), and `fold` and `lint` of a cell with a worktree go to its log there, as writes already did (the CLI prints a note). Not a line-ending problem, as first guessed on the issue. The cost: each message now reads and folds the logs it writes (root's and the cell's); small for logs of hundreds of entries. Lint reports views it catches half-written as "views unreadable" instead of crashing.

**Upgrading a project to v0.5**
- In the project's root `.claude/settings.json`, end the three guard commands (`hook-guard.ts`, `hook-bash.ts`, `hook-read.ts`) with ` || exit 2`, as this repo's (#38). Until then, a guard that can't load lets every call through.
- `node kernel/src/cli.ts cell refresh --name <cell>` for each cell (the same `|| exit 2` in its settings), commit, and land or merge main into each.
- Newly refused for sessions: `git reset --hard` (any commit), `git reset --keep/--merge` to another commit, `git clean` that deletes and `git stash` over paths that hold kernel-owned ones (the whole repository when none is named), and deleting or moving a folder that holds a log (`rm -rf cells/<x>`, `rm -rf docs`). Recovery lines that use them become `git revert`, or the operator runs them from their prompt.
- `fold` and `lint --cell cells/<x>` from main now go to the cell's worktree when it has one: the live log, the one `lint --all` already read.
- Nothing to run for #4, #5, #6, #7.

## v0.4 — guards by act, cells outside the repo (2026-10-23)

What the projects filed since v0.3, now GitHub issues on `Rwb3n/cellkit` (`maintainer/notes/`).

**Guards**
- **git's restores are writes** (#1). `git checkout -- docs/assumptions.md`, `git restore …` and `git checkout HEAD -- state/log/…` passed the shell guard: their text has no write verb. They are refused now, as are the same commands behind git's own options (`-C <dir>`, `-C<dir>`, `--work-tree`, `--git-dir`, `-c k=v`, `--no-pager`), which AI-MMO found passing its port (1e39484). So is a folder or pathspec that holds a kernel-owned path (`git checkout -- .`, `git restore state/log`, `"*.md"`): name the files you mean. Index-only forms stay open (`rm --cached`, `restore --staged`). The same git paths count for the project's own guarded paths (`guards.json` `protected`) and, in a cell, against its boundary.
- **The read guard follows `cd`, and `/d/x` is `D:/x` on Windows** (#1). `cd <another repo> && grep -r …` was judged against this project's `.env` (apify-actor-dev, callsheet); a Git Bash path was read as a folder of the project. A `cd` it can't judge (`$x`, `%x%`, `~`) is judged from the session's folder, as before.
- **Claude Code's own worktrees are guarded, and never merged into main** (#48). A subagent with `isolation: "worktree"` works in `.claude/worktrees/<name>` under root's hooks; its worktree's kernel-owned files could be restored from the shell, and its `worktree-*` branch merged into main past `cell land`'s audit and check. The shell guard now treats those worktrees as checkouts of their own and refuses merge, pull, cherry-pick, rebase and reset onto a `worktree-*` branch (Claude Code's `worktree-<name>`: documented for `claude --worktree`, seen for subagents). Lint warns on any worktree under `.claude/worktrees/`, whatever its branch, and on an unmerged `worktree-*` branch left behind. The rule: work reaches main through `cell land` or root's own commits.
- **The shell guard matches acts, not text** (#2; SF-DEV S5). A commit message, an `echo`'d string, a grep pattern, a `sed` script or a heredoc a program reads as data that only *names* a kernel-owned path, a `protected` path or a secret is no longer refused (root 2026-10-22: `grep -n "\.env" …`; apify-actor-dev: a script written by heredoc; SF-DEV). Write targets are checked one by one, quoted or not. The operator's acts (`approve`, `review decide`, `--accept-weaker`, `operator_only`) stay mention-strict.
- **Now refused, found on the way** (#2): what runs inside a command is judged like the command: `$(cat .env)` and backticks (also inside double quotes), `bash -c` / `pwsh -Command` / `cmd /c` strings, a heredoc fed to `bash` or `python -`, and an interpreter's `-e`/`-c` code. Now allowed: a search given only files (`grep -rn x a.ts`) reads those files, not the whole folder.

**Cells**
- **Cells' worktrees live outside the repository, where the project says** (#26). `guards.json` `"worktrees": { "home": "../.cells/<project>" }`, relative to the main checkout, puts every cell's worktree at `<home>/<cell>`: one folder for all projects' cells, instead of a `<repo>-cells/` sibling per project (processkit, modelkit: "worktrees littering the projects dir"). Without it, the sibling stays the default. A home inside the repository or by drive (`D:/…`, `/mnt/d/…`) is refused when the guards are checked: the project opens from Windows and WSL alike. `cell checkout` refuses a worktree inside the main checkout, `--path` included, and root's lint makes one made by hand an error: root's guards judge everything under the main checkout as root's, so a nested cell's files would be root's (tested 2026-10-22, `maintainer/notes/2026-10-22-native-agents.md`). Lint warns on a cell worktree that isn't at `<home>/<cell>` when a home is set.
- **Cells' worktrees are locked** (#22). `cell checkout` runs `git worktree add --lock --reason "cell <name>"`: a cell's worktree is kept, not throwaway (AI-MMO: a by-hand worktree outlived its session with 61 edited files), and `git worktree prune` leaves it. Root's lint warns on an unlocked one. A locked worktree deleted by hand stays registered; `cell checkout` then says how to release it (`git worktree unlock`, `git worktree prune`).

**Upgrading a project to v0.4**
- Add `.claude/worktrees/` to `.gitignore` (the template has it), or `git add -A` in main can commit a native worktree as an embedded repository. A session that restored a generated file with `git checkout --`, or discarded everything with `git checkout -- .`, now gets a refusal: regenerate with `node kernel/src/cli.ts fold`, and restore other files by name. Lint may now warn about native worktrees or `worktree-*` branches left from earlier sessions: remove them once nothing in them is needed.
- Cells' worktrees: existing ones in `<repo>-cells/` keep working where they are; nothing moves unless you want it to. Lint now warns that each is unlocked: `git worktree lock --reason "cell <name>" <path>`. Removing a cell's worktree now takes `git worktree remove -f -f` (one `--force` is refused for a locked one). To gather a project's cells in one folder, the operator approves `"worktrees": { "home": "../.cells/<project>" }` in `guards.json` (stage, `amend`, `approve`); new checkouts go there, and lint warns on each existing one elsewhere until it is moved, with no session open in it: `git worktree unlock <old>`, `git worktree move <old> <home>/<cell>`, `git worktree lock --reason "cell <cell>" <home>/<cell>`. A cell worktree inside the main checkout (e.g. `<repo>/.worktrees/<cell>`) is now a lint error: move it out the same way.

## v0.3 — the field survey (2026-10-18)

What SF-DEV, AI-MMO, callsheet, 01-HAIOS-PERS, project-archivist and live-stream-setup ran into (`maintainer/notes/`, `maintainer/backlog.md`).

**Cells, mail and headless runs**
- **A task reaches the cell's log when it is handed over**, not when it is sent. Sessions that read their log found queued tasks there, did them before the Stop hook handed them over, then did them again, and the first answer was lost (01-HAIOS-PERS, project-archivist). The brief now says a mail entry in the log is a record, never an instruction (`cell refresh` existing cells).
- **A progress note is not a reply.** While a task is in flight, the mail Stop hook holds back a final answer under 400 characters that reads as interim ("still running", "waiting for", "I'll report once it finishes"): it blocks and sends the session back to finish, at most 3 times per message, then files what it has (`mail.ts` `hold`, `test/mail.test.ts`). From SF-DEV (four lost replies) and AI-MMO (#112).
- **Headless runs are light and queue for room.** `cellrun` starts the session with `--strict-mcp-config` (no MCP servers: cells use none, and each loaded one costs helper processes). A run holds the cell's `runner.lock` (a second run refuses, exit 5) and waits, polling every 30 s, while 3 sessions run across cells or free memory is under 4 GB (`CELLKIT_MAX_RUNNERS`, `CELLKIT_MIN_FREE_MB`); after `--hold` (default 4 h) it gives up with the mail queued (exit 6). The choice to start is made under one lock, so two waiters never take the last slot together. From AI-MMO (dbd8995, 5e4b688), where the OS killed three runners for memory.
- **Dead runs and orphaned sessions.** `cellrun` records its session's pid in the runner lock: a session whose runner was killed keeps the cell's lock and a slot until it ends, and `cellrun` and `mail.ts release` refuse meanwhile (AI-MMO: a kill by process name took every runner). A run that ends with its task unfiled files the answer from its run log if the session finished one (marked recovered); if it died mid-task, the cell keeps the task and root gets a `blocked` mail. **`cellrun --resume`** recovers the answer from the last run's log, or starts a fresh session told the task and its partial work, whose reply goes to the original. Each run leaves `<log>.exit`. `mail.ts status` shows `run`. Before, a dead run filed "the task was not done" and the partial work was orphaned; a run killed with its parent left the cell stuck (project-archivist, seven days).
- **Cells run on main as it is.** Bedrock JSON (`kinds.json`, `guards.json`) is read from the main checkout, also by a cell's hooks and kernel in its worktree: a kind or guard approved on main is in force in every cell at once (SF-DEV: a cell refused claims of a kind approved that day). And `cellrun` merges main into the cell's worktree before the session starts, when the worktree is clean (in practice the first run after a land), so kernel and hook changes reach it too (SF-DEV: a read guard in kernel code didn't cover cells until root merged); uncommitted work, a merge in progress, or ignored files main would overwrite leave it alone; a conflict is aborted and the run stops (exit 7) with the mail queued. From AI-MMO (DEC-0013, 849252f).
- **Mail bodies can stay out of the logs.** `guards.json` `"mail": { "log": "hash" }` logs each message's sha256 and length; the body lives in the mailbox only. The default, `"body"`, logs it whole as before. An invalid `guards.json` logs hashes. From callsheet, whose rule against personal data in any log kept a component from being a cell.

**Guards**
- **The read guard.** No session, root's included, reads a secret (keys, `.env` but not `.env.example`, credential files and folders, shell histories) or a path the project lists in `guards.json` `"unreadable"` (by folder name anywhere on the disk), from Read, Grep (new `hook-read.ts`, matcher `Read|Grep`) or the shell (by act: `cat .env` is a read, a commit message naming it is not). A content search over a tree holding a secret must be narrowed. It fails closed. A floor, not a boundary: scripts read past it; an OS sandbox is the boundary (README). Ported from SF-DEV (secrets.ts, hook-read.ts). Existing cells get the new hook with `cell refresh`; a project's root `.claude/settings.json` needs the `Read|Grep` entry added (see this repo's).
- **Guards fail closed.** A check in `hook-bash` or `hook-guard` that throws, or input they can't parse, now refuses (exit 2, naming the error) instead of exiting 1, which let the command or write through unchecked. From AI-MMO (#134).
- **Kernel-owned paths are anchored.** The shell guard refuses `state/log|views|bedrock/` and `docs/assumptions.md` only as paths from the repo or a cell root, so a test fixture such as `test/fixtures/x/state/views/` can be written (SF-DEV: a cell gave up on static fixtures). The refusal names the path it matched (01-HAIOS-PERS: one listed paths the command never named).
- **No killing by name.** `taskkill /IM`, `pkill`, `killall`, `Stop-Process -Name` and pipes into `Stop-Process` are refused for every session; by pid is fine. From AI-MMO, where another project's `taskkill /F /IM python.exe` took every runner.
- **Write/Edit may use the temp folder** (outside the repo), as the shell already could (SF-DEV).

**The log**
- **The log has a lock.** Every append holds `state/log.lock` (git-ignored) and re-reads a stale tail, so writers at once never fork the chain: on Windows two took one id about 1 run in 20 without it. A dead holder's lock, or one older than 30 s, is taken over; a waiter gives up only when one holder keeps it 10 s (5 min at most), never while it changes hands. The lock nests within one process (`withLock`). From SF-DEV (S1), stress-tested with 8 processes (`test/lock.test.ts`).
- **`assume` without `--id`** takes one past the highest, chosen and appended under one hold of the lock: no probing for a free id with a throwaway entry, which the log keeps forever. From AI-MMO (d63993f).

**Fixes**
- **`cell land` read a path with its first letter cut off** when the first `git status` line was an unstaged change (` M docs/assumptions.md` → `ocs/assumptions.md`). Root's log commit then skipped the generated doc, and the next land refused it as root's own work. `dirty()` no longer trims git's output (`test/land-dirty.test.ts`). From SF-DEV.

**Upgrading a project to v0.3**
- Merge the kit, then `node kernel/src/cli.ts cell refresh --name <cell>` for each cell (new brief lines, the `Read|Grep` hook), commit, and land or merge main into each cell.
- Add the `Read|Grep` entry to the project's root `.claude/settings.json` (copy this repo's).
- Add `**/state/log.lock` to `.gitignore`.
- `cellrun` has new exit codes: 5 (a live run or orphaned session holds the cell), 6 (no room within `--hold`), 7 (merging main into the worktree failed). A cell whose session died: `cellrun --resume`, not `release`.
- Optional, in `guards.json` (operator approves): `"unreadable"` paths, and `"mail": { "log": "hash" }` to keep mail bodies out of the logs.
- The read guard now refuses `cat .env` and unnarrowed recursive searches over a folder holding one, for root too. A project that relied on reading its own `.env` in a session: let the tool read it (`process.loadEnvFile`).

## v0.2 — lessons from the projects (2026-10-09)

What carnet, 01-HAIOS-PERS, PS5-STUDY, SF-DEV, PORTOFOLIO-MANAGER, loyalty-code-app, AI-MMO and DTG ran into.

**Fixes**
- `worktree.test.ts` failed (25/26) whenever the kernel's tests ran from a cell's worktree, which is what the brief tells every cell to do. It now takes the main checkout's `node_modules`.
- `cli.ts --cell cells/<x>` run from the main checkout wrote the main checkout's copy of a cell that has a worktree. That forked the cell's chain. Writes now land in the worktree, as mail already did. `cell refresh` does the same.
- A headless run that died mid-task left the cell refusing every later run (exit 3). `cellrun` now files a reply saying the task was not done; `mail.ts release --as <cell>` does the same by hand.
- The shell had no cell boundary (`cp x ../../kernel/…` passed). Redirects and file verbs aimed outside the cell are now refused.
- Removed carnet's `docs/models` leftover from `hook-guard.ts`.

**A configuration surface: nothing in `kernel/` to edit** (README, "Configuring it for your project")
- Bedrock holds `.json` docs the kernel reads. They go live only when the operator approves, and `amend` and `approve` refuse one that doesn't check.
- `state/bedrock/kinds.json`: your claim kinds, each a JSON Schema, merged into the kit's claim schema. A proposal is checked against every claim already logged, so a kind can't be dropped or narrowed while claims of it exist.
- `state/bedrock/guards.json`: your operator-only commands and script-written paths, read by both hooks. It replaces forks of `hook-bash.ts` and `hook-guard.ts`; see `templates/guards.example.json`.
- `guards.json` → `cells.<x>.owns`: repo paths a cell owns beyond its folder. Write/Edit, the shell guard, `cell audit`, `cell land`, the brief and lint all honour them; lint errors if a tracked file has two owners.
- `cell rebind`: a cell's `binding.json` is root's to change, and each change is logged on the cell's log. A cell can't edit its own binding, and lint catches a hand edit.

**New commands**
- `cell land`: root's whole loop in one command, which undoes itself if any step fails.
- Bedrock: `stage --doc` records the base, `amend` refuses a stale copy, and `approve --proposal <entry>` (with several proposals pending it refuses to guess).
- `lint --all` lints every cell's log too.
- Assumptions can be parked with `evidence --note "parked: …"`.
- `templates/ROOT.md`: root's handover (role, where state lives, routines, lessons).

**Cell brief** (existing cells: `cell refresh --name <cell>`)
- A cell may write anywhere in its folder except its log and its binding, plus the paths it owns. The old brief listed five folders, and a cell refused allowed work over it.
- `exit/` and `test/` are created at birth. Durable output goes in `exit/`, because `state/out/` is ignored except `metrics.json`.
- Work synchronously: no background work or sub-agents left running at the end of a turn.

**Taking it into a project**, in this order:
1. Merge the kit (README, "Using it in a project").
2. **Kinds**, if you added any to `kernel/schemas/claim.schema.json`:
   - write them to `state/bedrock/proposed/kinds.json` and amend;
   - the operator approves;
   - only then take the kit's `claim.schema.json`.

   The two enums merge, so lint stays green at each step.
3. **Guards**, if you edited `kernel/src/hook-*.ts`:
   - move the rules to `state/bedrock/proposed/guards.json`, amend, and the operator approves;
   - then take the kit's hook files as they are.
4. **Bindings**: lint now compares each cell's `binding.json` with its log. If one was edited by hand, run `node kernel/src/cli.ts cell rebind --name <cell>` to record it.
5. Run `cell refresh` for each cell, then land it.
